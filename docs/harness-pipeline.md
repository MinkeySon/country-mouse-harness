# 하네스 파이프라인 (R3)

> 목적·범위: `harness-purpose.md` / 판정 기준: `story-service.md`, `design.md`

## 단계

| 단계 | story-work | 입력 | 출력 |
|---|---|---|---|
| S1 레퍼런스 수집 | 1 | 유저스토리 번호 | 선별한 레퍼런스 목록 (repo 파일) |
| S2 분석·화면 설계 | 2+3 | 레퍼런스 목록, prd.md, design.md | 화면 설계서, 키스크린 2~3개 (repo 파일) |
| S3 키스크린 그리기 | 4 | 화면 설계서 | Figma 390×844 프레임 2~3개 |
| S4 가이드 검토 | 7 | Figma 프레임, design.md, story-service.md | 검토 결과, 위반 목록 (repo 파일) |

## 단계별 규칙

### S1 레퍼런스 선별 (story-work 1번 멈칫 대응)
- uibowl 검색 결과 중 최종 3~5개만 남긴다.
- 레퍼런스마다 연결된 유저스토리 요소 1개 + 반영할 점 1줄이 있어야 한다.
- 이유가 비어 있는 레퍼런스는 탈락.

### S2 → S3 사전 확인 (story-work 4번 멈칫 대응)
- 설계서의 화면마다 유저스토리 요소를 1개 이상 가리킨다.
- 컴포넌트는 design.md에 정의된 이름만 쓴다.
- 실패 시 S2로.

## 되돌아가는 지점

| 실패 위치 | 되돌아갈 곳 |
|---|---|
| S1 선별 규칙 | S1 |
| S2 사전 확인 | S2 |
| S4 가이드 위반 | S3 |
| 같은 단계 2회 실패 | 중단, 사람에게 넘김 |
