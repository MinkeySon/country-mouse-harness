# 시골쥐 앱 PRD — 여러 은행의 입출금을 하나의 캘린더로 모아 보는 소비 기록 앱

> 이 문서는 시골쥐의 제품 요구사항 정의서입니다. 비주얼 톤과 디자인 규칙은 `design.md`를 기준으로 합니다.
> 작성자가 명시하지 않아 **제가 임의로 정한 항목은 `[가정]`** 으로 표시했고, 확정이 필요한 항목은 **15. 열린 질문**에 모아두었습니다.

---

## 1. 배경

은행 계좌를 여러 개 쓰는 사람은 돈이 어디서 들어오고 어디서 나갔는지 확인하려면 은행마다 앱을 열어 내역을 보고, 그 내용을 따로 정리해야 합니다.

- 월급 통장, 생활비 통장, 저축 통장, 모임 통장이 서로 다른 은행에 흩어져 있습니다.
- 은행 앱은 자기 은행의 내역만 보여주므로 "오늘 하루 총 얼마를 썼는지"를 한눈에 알 수 없습니다.
- 은행 앱의 내역은 상호명 텍스트 위주라서 "그날 내가 어디를 돌아다니며 썼는지"를 떠올리기 어렵습니다.
- n빵, 대신 결제, 더치페이처럼 **통장에는 찍히지 않는 맥락**(누가 얼마를 아직 안 보냈는지 등)은 기억이나 메신저에 의존하게 됩니다.

시골쥐는 이 번거로움을 없애기 위해, **흩어진 입출금 이벤트를 한 곳에 모으고, 날짜(캘린더)와 장소(지도)로 다시 보여주며, 사용자의 메모를 함께 남길 수 있는 앱**입니다.

---

## 2. 제품 비전

시골쥐는 **"내 돈의 하루를 한 화면에서 되돌아보는 소비 다이어리"** 입니다.

> 시골쥐는 여러 은행의 입금·출금 이벤트를 하나의 캘린더로 통합하고, 그날의 지출을 지도 위 장소와 사용자의 메모로 함께 기억하게 해주는 소비 기록 앱입니다.

### 제품 원칙

1. **모으기가 먼저다** — 사용자가 은행을 한 번 연결하면 이후에는 아무것도 하지 않아도 내역이 쌓입니다.
2. **날짜에서 시작해 장소로 내려간다** — 연 → 월 → 일 → 은행 → 거래 → 지도 순으로 점점 자세히 봅니다.
3. **통장이 모르는 것은 사용자가 적는다** — 자동 수집된 내역 위에 사용자의 메모를 얹습니다.
4. **읽기 전용이다** — 시골쥐는 돈을 옮기지 않습니다. 조회만 합니다. (신뢰의 전제)

---

## 3. 핵심 유저스토리

### 3-1. 은행 여러 개를 쓰는 사용자로서

**여러 은행 계좌를 쓰는 사용자로서**, 은행 앱을 하나씩 열지 않고 한 곳에서 내 입금·출금 내역을 보고 싶다.

### 3-2. 한 달 소비를 돌아보는 사용자로서

**이번 달 소비를 돌아보고 싶은 사용자로서**, 월 캘린더에서 날짜마다 그날 입금 합계와 출금 합계를 바로 보고 싶다. 돈을 많이 쓴 날이 어느 날인지 한눈에 알고 싶다.

### 3-3. 특정 날을 자세히 보고 싶은 사용자로서

**특정 날짜의 소비가 궁금한 사용자로서**, 그날 내역을 은행별로 나누어 보고, 은행을 눌러 그 은행에서 나간 거래를 확인하고 싶다.

### 3-4. 어디서 썼는지 궁금한 사용자로서

**어디서 돈을 썼는지 기억이 안 나는 사용자로서**, 거래를 누르면 지도에 위치가 찍히고 얼마를 썼는지 보고 싶다.

### 3-5. 함께 쓰고 정산하는 사용자로서

**n빵을 하거나 대신 결제한 사용자로서**, 그 거래에 "누가 얼마 안 냈다" 같은 메모를 남기고, 나중에 받을 돈이 남아 있는지 다시 확인하고 싶다.

### 3-6. 연간 흐름을 보고 싶은 사용자로서

**1년 단위로 돈의 흐름을 보고 싶은 사용자로서**, 연 캘린더(12개월)에서 월별 입금·출금 추이를 보고 싶다.

---

## 4. 사용자들의 상황

- 사용자는 주거래 은행 외에 급여, 카드 대금, 저축, 모임 등 목적별로 은행을 나눠 씁니다.
- 대부분의 은행 앱은 상호명 문자열만 보여주며, 위치·메모·분류가 부족합니다.
- 사용자는 가계부를 직접 쓰는 것을 부담스러워 합니다. 그래서 **자동 수집이 기본**, 수동 입력은 **보조**여야 합니다.
- 금융 정보를 다루므로, 사용자는 "이 앱이 내 돈을 건드리지는 않는가", "내 정보가 어디에 저장되는가"를 가장 먼저 의심합니다.
- 소비 맥락(누구와, 왜)은 통장 내역에 없습니다. 이 맥락이 시골쥐가 다른 은행 통합 앱과 달라지는 지점입니다.
- 초기 앱은 기능을 많이 넣기보다, **연결 → 캘린더 → 일별 상세 → 지도 → 메모**의 핵심 루프를 먼저 완성해야 합니다.

## 5. 핵심 정보 구조

앱은 최소한 아래 화면 계층을 가져야 합니다.

```txt
[홈 / 캘린더]                     ← 앱의 중심 화면
 ├─ 연 보기   12개월 그리드, 월별 입금/출금 합계
 ├─ 월 보기   달력, 날짜별 입금/출금 합계
 └─ 일 보기   해당 날짜의 은행별 내역
      └─ 은행별 거래 목록
           └─ 거래 상세  ← 지도(위치 핀) + 금액 + 메모/정산 기록

[계좌 관리]
 은행 연결/해제, 연결 상태, 마지막 동기화 시각

[검색 / 필터]  (MVP 이후)
 기간, 은행, 금액, 상호명, 메모 검색

[설정]
 보안(앱 잠금), 알림, 데이터 삭제, 로그아웃
```

### 화면 이동 원칙

- 캘린더의 **연/월/일은 탭이 아니라 확대·축소 관계**입니다. 연 → 월 → 일로 들어갔다가 뒤로 돌아오면 이전 위치가 유지됩니다.
- 일 보기에서 **은행 단위로 접고 펼치는 그룹**이 기본입니다. 은행을 눌러야 그 은행의 거래가 나타납니다.
- 거래를 누르면 **지도 화면이 열리고 핀과 금액이 함께 표시**됩니다.

## 6. 기능 요구사항

### 6-1. 은행 연결과 내역 수집

사용자가 여러 은행 계좌를 연결하면, 입금·출금 이벤트가 자동으로 수집되어야 합니다.

필수 기능:

1. 은행/계좌 연결 (인증은 금융 데이터 중개 사업자를 통해 진행) `[가정]`
2. 연결된 계좌 목록 및 연결 상태 확인
3. 계좌별 별칭 설정 (예: "월급통장")
4. 최초 연결 시 과거 내역 가져오기 (`[가정]` 최근 3개월)
5. 이후 자동 동기화 (앱 진입 시 + 주기적 갱신) 및 수동 새로고침
6. 연결 해제 시 해당 계좌의 저장 데이터 삭제 옵션
7. 중복 거래 제거 (같은 거래가 두 번 들어오지 않도록)
8. 동기화 실패·재인증 필요 상태 안내

수집 필드 (계좌 거래 1건당):

```txt
거래일시, 입금/출금 구분, 금액, 거래 후 잔액,
상대방 표기(적요/상호명), 은행, 계좌
```

> ⚠ 기술 제약 (반드시 확인 필요, 12번 리스크 참조)
> - 은행 계좌 내역에는 **좌표가 없습니다.** 위치 표시는 상호명을 지오코딩해서 얻습니다.
> - **신용카드 결제는 계좌에는 "카드대금" 한 줄**로만 나갑니다. 가게별 지출과 위치를 보려면 **카드 승인 내역**이 별도로 필요합니다.

---

### 6-2. 캘린더 보기 (연/월/일)

입금·출금 내역을 **연, 월, 일** 단위의 캘린더 형식으로 볼 수 있어야 합니다.

**월 보기 (기본 화면)**

1. 달력 그리드, 각 날짜 칸에 **입금 합계(파랑) / 출금 합계(회색·검정)** 표시
2. 월 상단 요약: 이번 달 총 입금, 총 출금, 차액
3. 지출이 큰 날을 시각적으로 구분 (금액 구간별 강도 표시)
4. 이전/다음 달 이동, "오늘" 바로가기
5. 날짜를 누르면 일 보기로 이동
6. 메모가 있는 날짜는 작은 표시(점)로 구분

**연 보기**

1. 12개월 그리드, 월별 총 입금/출금
2. 월을 누르면 해당 월의 월 보기로 이동
3. 연간 총 입금/출금 요약

**일 보기**

1. 상단: 선택한 날짜, 그날 입금 합계·출금 합계
2. **은행별 그룹** 목록 (은행 로고/이름, 그 은행의 그날 입금·출금 합계, 거래 건수)
3. 은행 그룹을 누르면 그 은행의 거래 목록이 펼쳐짐 (시간, 상대방, 금액, 입/출금)
4. 이전 날/다음 날로 스와이프 이동

---

### 6-3. 거래 상세와 지도

일 보기에서 은행을 눌러 거래를 선택하면, **어디서 지출이 발생했는지 지도에 위치가 표시**되어야 합니다.

필수 기능:

1. 거래 상세 화면: 금액, 시간, 상대방(상호명), 은행/계좌, 분류
2. **지도에 위치 핀 표시** + 핀 위 말풍선에 **지출 금액** 표시
3. 은행 단위로 볼 때는 **그날 그 은행의 모든 지출 위치를 한 지도에** 핀으로 표시 (핀마다 금액)
4. 핀을 누르면 해당 거래 상세로 이동
5. 위치를 찾지 못한 거래 처리
   - 지도에는 표시하지 않고 "위치 미확인" 목록으로 분리
   - 사용자가 **위치를 직접 지정/수정**할 수 있음 (수정한 값은 같은 상호명에 다음부터 재사용)
6. 온라인 결제·이체·자동이체 등 **위치가 없는 거래**는 "위치 없음"으로 구분 (오류가 아님)
7. 상호명 → 위치 변환 결과는 캐시하여 재사용

---

### 6-4. 사용자 기록 (메모 / 정산)

사용자는 거래에 **자신만의 기록**을 남길 수 있어야 합니다. (예: n빵을 했는데 누가 얼마를 안 냈다.)

필수 기능:

1. 거래에 **자유 메모** 작성/수정/삭제
2. **정산 기록** (n빵/대신 결제)
   - 참여자 추가 (이름은 사용자가 직접 입력)
   - 참여자별 부담 금액 (균등 분할 버튼 + 개별 수정)
   - 참여자별 **받음 / 안 받음** 상태 체크
   - 아직 받지 못한 총액 자동 계산 (예: "3명에게 45,000원 미수")
3. 태그 (예: `#회식`, `#데이트`) `[가정]`
4. 메모/정산이 있는 거래·날짜에 캘린더/목록에서 표시
5. **미정산 모아보기**: 아직 못 받은 돈이 있는 거래를 한 목록으로 보기
6. 정산 완료 처리 시 완료 일시를 기록

> 정산 기록은 **기록용**입니다. 실제 송금·독촉 메시지 발송은 하지 않습니다. (MVP 제외 / 이후 검토)
> 정산 금액은 은행 내역의 금액을 바꾸지 않습니다. 원본 거래 금액과 사용자의 기록은 항상 분리해서 저장합니다.

---

### 6-5. 분류와 통계 (MVP 이후 · Phase 2)

1. 거래 자동 분류 (식비/교통/쇼핑 등) 및 사용자 수정
2. 분류별/은행별 지출 비율
3. 월별 추이 비교
4. 예산 설정 (선택)

---

### 6-6. 알림

알림은 최소한으로 설계합니다.

1. 은행 연결 만료/재인증 필요
2. 동기화 실패
3. 미정산 리마인더 (사용자가 켠 경우만) `[가정]`
4. ~~신규 입출금 실시간 알림~~ (MVP 제외 — 은행 앱이 이미 제공)

---

### 6-7. 보안과 개인정보

금융 앱이므로 다음은 **MVP 필수**입니다.

1. 앱 잠금 (생체인증/PIN)
2. **읽기 전용 권한만 요청** — 이체·결제 권한은 요청하지 않음
3. 은행 자격증명(ID/비밀번호)을 시골쥐가 직접 저장하지 않음
4. 저장 데이터 암호화 (전송 구간·저장 구간)
5. 백그라운드 전환 시 금액 화면 가림
6. 계정 삭제 시 모든 거래·메모 데이터 완전 삭제
7. 개인정보 처리방침, 금융 정보 수집·이용 동의 화면

---

## 7. 권한 구조

### 7-1. 비로그인

- 서비스 소개 화면과 가입 유도만 볼 수 있음
- 샘플 데이터로 캘린더/지도 체험 (`[가정]` 데모 모드)

### 7-2. 로그인 사용자

- 은행 연결/해제
- 자기 데이터의 캘린더·거래·지도 조회
- 메모/정산 기록 작성

> 사용자의 데이터는 **본인만** 볼 수 있습니다. 공유 기능(가족/커플 공동 가계)은 Phase 3 이후 검토합니다.

### 7-3. 운영자

- 사용자 거래 데이터에는 **접근하지 않습니다.**
- 서비스 상태, 오류 로그(개인 식별·금액 정보 제외), 공지 관리만 담당합니다.

## 13. 조건

- 시골쥐는 **조회 전용**입니다. 이체, 결제, 잔액 변경 기능은 어떤 단계에서도 제공하지 않습니다.
- 원본 거래 데이터는 사용자가 수정할 수 없으며, 사용자의 기록(메모/정산/위치 수정)은 원본과 분리해 저장합니다.
- 사용자 데이터는 본인만 조회할 수 있습니다.
- 필요한 이미지·아이콘·은행 로고·더미 데이터는 직접 조달하되, 비주얼 톤과 디자인 규칙은 **`design.md`(디자인 시스템 문서)를 기준**으로 합니다. (흰 바탕 `#FDFDFD`, 파란 포인트 `#0055FF`, Pretendard)
- 은행 로고 사용은 각 은행의 이용 조건을 확인해야 합니다. 확인 전까지는 이름 텍스트 + 단색 이니셜 아이콘으로 대체합니다.
- 최종적으로 보는 것은 보기 좋은 화면뿐 아니라 **AI 에이전트가 읽고 이어서 작업할 수 있는 데이터로서의 디자인**입니다.

## 14. 이렇게 평가해요

### 문제 해결의 완성도

여러 은행의 내역이 **하나의 캘린더로 통합**되어, 은행 앱을 따로 열지 않아도 날짜별 입금·출금을 확인할 수 있는지를 봅니다.

### 탐색 흐름의 완성도

연 → 월 → 일 → 은행 → 거래 → 지도로 이어지는 **점진적 상세 흐름**이 화면 구조에서 자연스럽게 드러나야 합니다. 특히 "날짜를 고르고, 은행을 누르고, 지도에서 어디서 얼마 썼는지 확인"하는 핵심 경로를 3~4번의 탭으로 끝낼 수 있어야 합니다.

### 기록 기능의 완성도

n빵 같은 실제 상황에서 "누가 얼마를 안 냈는지"를 기록하고 나중에 다시 찾아 완료 처리할 수 있어야 합니다. 원본 거래와 사용자 기록이 분리되어 있는지도 함께 봅니다.

### 예외 상황 처리

위치 미확인, 위치 없음(이체/온라인), 동기화 실패, 재인증 필요, 데이터 없는 날 같은 **빈 상태와 오류 상태**가 화면으로 설계되어 있는지 봅니다.

### 디자인 완성도

금융 정보를 다루는 앱에 맞게 **신뢰감 있고 깔끔하며 숫자가 한눈에 읽히는** 화면이 필요합니다. 입금은 파랑, 출금은 중립색으로 구분하는 등 색을 의미 있게 씁니다.

> 비주얼 표현은 `design.md` 기준을 따르며, 토큰·컴포넌트가 `design.md` 규칙을 위반하지 않았는지를 함께 봅니다.

### 데이터 구조화

거래, 위치, 메모, 정산이 AI 에이전트가 읽고 이어서 작업할 수 있는 구조로 설계되어야 합니다. 텍스트 덩어리나 이미지 중심의 디자인만으로는 부족합니다.

## 15. 열린 질문 (확정 필요)

아래는 제가 `[가정]`으로 채운 항목입니다. 다르게 생각하시면 알려주세요.

1. **카드 결제를 어떻게 다룰까요?** 현재 가정은 계좌 입출금만 다루고, 카드 승인 내역은 Phase 0에서 가능 여부를 확인한다는 것입니다. 카드 연동이 안 되면 "지도에 찍히는 지출"이 크게 줄어들 수 있어 핵심 결정 사항입니다.
2. **데이터 수집 방식** — 오픈뱅킹, 마이데이터, 또는 스크래핑 기반 중개 서비스 중 무엇을 쓸지 정해지지 않았습니다. 개인 프로젝트인지 사업화 계획이 있는지에 따라 달라집니다.
3. **플랫폼** — 모바일 앱(iOS/Android)인지, 웹 앱인지? (현재 가정: 모바일 우선)
4. **지원 국가/통화** — 한국 원화만 가정했습니다.
5. **정산 참여자** — 이름을 직접 입력하는 방식으로 가정했습니다. 연락처 연동이 필요한지?
6. **앱 이름 표기와 톤** — "시골쥐"라는 이름(서울쥐/시골쥐 이솝우화의 소박한 이미지)을 브랜딩에 살릴지, 캐릭터를 쓸지?
7. **수익 모델** — 현재 문서에는 없습니다. 무료, 구독, 광고 중 어떤 방향인지 정해지면 추가하겠습니다.
8. **과거 내역 범위** — 최초 연결 시 최근 3개월로 가정했습니다.
