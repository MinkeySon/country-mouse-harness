# 시골쥐 유저스토리

> 출처: `docs/prd.md`. PRD에 있는 내용만 정리했습니다. 대상 사용자는 서비스 사용자 한 종류입니다.

## 유저스토리

| # | 유저스토리 | PRD 근거 |
|---|---|---|
| 1 | 여러 은행 계좌를 쓰는 사용자가 은행 앱을 하나씩 열지 않고 한 곳에서 입금·출금 내역을 본다. | 3-1, 2장 비전 |
| 2 | 사용자가 월·연 캘린더에서 날짜별·월별 입금 합계와 출금 합계를 보고, 돈을 많이 쓴 날을 한눈에 파악한다. | 3-2, 3-6, 6-2 |
| 3 | 사용자가 특정 날짜의 내역을 은행별로 나눠 보고, 은행을 눌러 그 은행의 거래를 확인한다. | 3-3, 6-2 일 보기 |
| 4 | 사용자가 거래를 눌러 지도에서 지출 위치와 지출 금액을 확인한다. | 3-4, 6-3 |
| 5 | n빵이나 대신 결제를 한 사용자가 거래에 메모(누가 얼마 안 냈는지 등)를 남기고, 받을 돈이 남아 있는지 다시 확인한다. | 3-5, 6-4 |

## 이 서비스에서 어기면 안 되는 것

| # | 어기면 안 되는 것 | PRD 근거 |
|---|---|---|
| A | 시골쥐는 조회 전용이다. 이체, 결제, 잔액 변경 기능은 어떤 단계에서도 제공하지 않는다. | 13장 첫 항목 (2장 원칙 4, 6-7과 일치) |
| B | 은행에서 받은 원본 거래 데이터는 사용자가 수정할 수 없다. 메모·정산·위치 수정은 원본과 분리해서 저장한다. | 13장 두 번째 항목 (6-4, 8장 Transaction과 일치) |

## 범위 메모

- 은행 연결 자체는 유저스토리에 넣지 않았습니다. 데이터 수집 방식이 아직 확인되지 않았기 때문입니다.
- 운영자 유저스토리는 없습니다. 서비스 사용자만 다룹니다.
