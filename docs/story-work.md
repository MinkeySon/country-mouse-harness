# 시골쥐 디자인 작업 방식 (AI 없이 손으로 했던 마지막 경험)

> 이 문서는 "내가 실제로 어떻게 작업했는지"를 정리한 것입니다.
> `story-service.md`("무엇을 위한 일인지"의 기준)와는 다른 내용이므로 섞지 않습니다.

## 작업 흐름 (원문)

1. 나는 uibowl에서 경쟁사 레퍼런스를 수집한다.
2. 레퍼런스를 토대로 분석하고 우리 서비스에 반영할 부분을 가져온다.
3. 분석내용을 토대로 우리 서비스 화면 설계 문서를 구체화한다.
4. Figma에 레퍼런스와 화면설계서를 반영한 UI 키스크린 2~3개를 390×844 사이즈로 그린다.
5. 내부 관계자들과 협의 후 컨셉 시안을 확정한다.
6. 컨펌된 시안을 기반으로 디자인 토큰과 컴포넌트를 제작하고, 화면 디자인에 들어간다.
7. 완성된 시안에서 토큰이나 컴포넌트가 우리 가이드에 위반된 부분이 없는지 검토한다.

## 명사 · 게이트 · 경계

| # | 명사 (산출물) | 멈칫 (게이트) | 넘김 (에이전트 경계) |
|---|---|---|---|
| 1 | 경쟁사 레퍼런스 | **있음**: 레퍼런스가 너무 많아서 뭘 남길지 기준이 애매하다 | uibowl (도구) |
| 2 | 분석 내용, 서비스에 반영할 부분 | 없음 | 직접 함 |
| 3 | 화면 설계 문서 | 없음 | Figma에 작성 (도구) |
| 4 | UI 키스크린 2~3개 (390×844) | **있음**: 그려본 뒤에야 안 맞는 걸 알아서 다시 그리게 된다 | Figma (도구) |
| 5 | 확정된 컨셉 시안 | 없음 | 내부 관계자들 (사람) |
| 6 | 디자인 토큰, 컴포넌트, 화면 디자인 | 없음 | Figma에서 제작 (도구) |
| 7 | 가이드 위반 검토 결과 | 없음 | 직접 검토, 기준은 `design.md` |

## 요약

- **게이트 후보 2개**: 1번(레퍼런스를 남길 기준), 4번(그리기 전에 맞는지 확인)
- **도구 경계**: uibowl, Figma
- **사람 경계**: 5번 내부 관계자 (멈칫은 없다고 확인함)
- **직접 하는 일**: 2번 분석, 7번 가이드 검토
